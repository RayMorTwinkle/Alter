# ADR-0022 主会话统一通过 send_message 对用户说话

- 状态：[部分被 ADR-0025 取代](0025-reply-by-default-stay-silent.md)
- 日期：2026-11-24
- 修订：ADR-0012 的主会话回复与通知投递规则

## 背景

11 月 22 日，五次任务报告的结果都没有送到飞书。任务回投后，模型可以在普通正文里写出完整结果，用户却收不到。旧规则要求模型根据唤醒来源判断普通回复会送到哪里，还要决定是否再调用通知工具。

## 决策

主会话对用户说话一律调用 `send_message({ text })`，包括回答提问、汇报任务结果和告知值得关注的巡检发现。用户发来的消息通常需要回复。巡检等主动回合可以静默结束。

工具只接受最多 4000 字的全文，固定立即投递，安静时段也生效。网页输入触发的整轮消息只在网页显示。其他回合可由已配对的飞书账号接收纯文本。定时提醒和分诊继续按各自的规则处理。

网页时间线展示模型提供的思考、普通正文草稿、工具调用和实际发出的消息。巡检沿用简短的工具调用提示。

## 备选方案

曾考虑用飞书卡片展示处理过程。卡片可以改变呈现方式，却无法解决模型把最终答复留在草稿里的问题。用户选择了一个发送工具和纯文本投递。

曾考虑在回合结束时自动转发正文兜底。这会让草稿也成为对外消息，并可能重复发送工具已经发过的内容。用户要求保留单一发送规则，遗漏通过统计和逐例复盘改进。

## 后果

每条主会话消息都可以关联到一次明确的工具调用。模型漏调用时，用户仍可能收不到答复。账本保留原始输入引用，便于对照当时的草稿、工具记录和通知查明原因。

## 如何验证

按时间窗口查看 `/api/stats` 的 `unreplied`，抽查「用户消息未回复」的账本记录，尤其是经过多轮工具调用的对话。对任务报告另行核对通知与飞书投递记录，主动回合的静默不计入用户未回复数。把可复现的漏发实例加入回归用例，再调整提示与工具说明。
