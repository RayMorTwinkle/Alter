# ADR-0008 浏览器插件基于 ego，点击按低风险放行

- 状态：已接受；部分被 ADR-0018 修订
- 日期：2026-11-22

## 背景

浏览器是第一个"真实"的 Connector（#5）。两个问题需要先定：

1. **驱动方式**：自己起一个无头浏览器，还是驱动用户日常使用的 ego 浏览器。
2. **风险分级**：#3 之后，任务打开任何网页就会被标记为已污染，此后 `external-send` 及以上的调用不论档位都要用户批准。如果点击算 `external-send`，浏览器几乎无法自动使用；如果算低风险，模型可能点到"发送""购买"之类的按钮。

## 决策

- **驱动 ego**：通过 `ego-browser nodejs` 运行脚本，使用用户日常的 ego 环境（含登录态）。每个任务会话独占一个 ego TaskSpace，空间编号记在会话文档里，任务结束或插件停止时关闭。
- **风险分级（用户决定）**：
  | 动作 | 副作用 |
  |---|---|
  | 打开网址、读取页面快照、滚动 | `read` |
  | 点击（任何元素） | `write-local` |
  | 填写输入框、按键（Enter 可能提交表单） | `external-send` |
  | 关闭空间 | `write-local` |
- 页面内容一律标记为不可信（`details.untrusted`），包在 `<external source="browser">` 中并截断。

## 备选方案

- **点击全算对外**：最安全，但自动浏览基本不可用。
- **按元素语义分级**（链接算读、按钮算对外）：更精细，但判断依赖页面结构，容易被页面伪装绕过。
- **独立的干净环境**：没有登录态，安全但多数真实任务做不了。

## 后果

- 接受风险：模型可能误点会产生副作用的按钮（例如一键购买、已填好表单的提交按钮）。缓解：填写与按键必须用户批准，所以大部分提交需要先经过一次审批；点击的完整记录在审计与任务过程里可查。
- 使用日常环境意味着任务能访问用户已登录的网站，权限等同用户本人；这正是需要污点追踪与审批的原因。
- 之后若误点成为实际问题，再引入"高风险按钮"识别或改为按语义分级。

## 如何验证

- 离线测试：假的 ego 运行器验证脚本生成、空间复用与关闭、内容截断与不可信标记、各动作的副作用声明。
- 真机：打开公开网页、读快照、点击链接全程不弹审批；在搜索框填写时弹审批。

## 修订

原先的 20 个专用工具只覆盖了部分 ego-browser API，下载、iframe 子树快照等操作仍需额外封装。自 #121 起，打开、快照、点击、填写、按键、滚动、截图、交接和关闭保留为专用工具。其余操作通过 `browser_run` 执行异步 Node.js 脚本。会话继续复用同一个任务空间，插件向脚本提供当前的 `task` 和选中的 `page`，并负责空间的创建、接管和结束。脚本的 JSON 返回值和日志沿用浏览器输出的截断与转义规则。

按 ADR-0021 的审批口径，点击、填写、按键和 `browser_run` 归为 `write`。审批模型可结合调用参数中的脚本与当前页面的网址、标题判断。其余专用工具及新增的 `browser_guide` 归为 `read`。`browser_guide` 从已安装的 CLI 读取并缓存完整指南，使脚本可以使用与本机版本一致的 API。
