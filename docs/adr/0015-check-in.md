# ADR-0015 回访：每周问用户几个问题

- 状态：已接受
- 日期：2026-11-23

## 背景

Alter 的很多判断没有直接的对错信号：自动审批顺不顺手、巡检找的事是不是用户想做的、画像里"猜的"条目对不对。用户偶尔点"有用 / 没用"不够。需要一个定期、低打扰的方式直接问用户，同时服务三件事：评测效果、完善画像、给开发收集反馈。

## 决策

**一、频率与时机。** 默认每周一次，在用户刚活跃过、且没有正在进行的对话时发出。连续两次被整体跳过，下次间隔加倍。

**二、问题从哪来。** 每次由一次低思考强度的模型调用从下面几处挑题：

- 记忆里标"猜的"条目（"你是不是……？"）
- 指标异常：巡检采纳率偏低、审批模型与用户决定不一致、某类通知常被点"没用"
- 近期上线或改动的功能（"最近按说明自动允许好用吗？"）
- 沟通方式（"想让我说得更浅显一点吗？"）

**三、题量。** 按"影响大 × 最没把握"排序，默认展示 3–5 题；答完可以点"再来几题"。每题都可跳过，常被跳过的题型自动减少。

**四、题型。** 以单选 / 多选为主，3–5 个选项加一个"其他（自己写）"；少量开放题。避免只有两个选项。

**五、答案去哪。**

- 画像类：直接更新记忆（确认、修改或删除"猜的"条目）。
- 评测类：进统计页，形成满意度时间序列。
- 全部答案按周汇总成"产品反馈"，只存本机，可导出给开发者。

**六、渠道。** 飞书卡片与 Web 都能答，任一端答过即同步。

## 备选方案

- **固定 3 题**：信息不够；用户愿意多答时浪费机会。
- **在日常对话中随时插问**：打断用户，先不做。
- **只用隐式信号**：看不出"为什么"，也无法确认画像。

## 后果

- 正面：评测、画像、开发反馈共用一个低成本入口。
- 负面：用户可能疲劳；靠频率上限、跳过降频、可关闭来控制。
