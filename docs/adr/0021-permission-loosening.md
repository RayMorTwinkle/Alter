# ADR-0021 放宽工具权限，在实际调用时审批

- 状态：已接受
- 日期：2026-11-25
- 修订：ADR-0018 第一、三、四条中的工具效果、权限说明、租用审批和用户决定

## 背景

11 月 25 日正式环境暴露了四个问题。用户给出网址后又补充了几句，三句窗口把网址挤掉了。模型写的租用理由让审批卡在工具启用阶段。用户点过允许，模型重试时改写参数，又被要求确认。浏览器交接超时后，控制权留在用户手里，后续调用持续失败。

## 决策

- 主会话用 `enable_tool` 启用能力或单个动作，租用直接通过。任务直接调用工具。派单时把主会话近期用户原话和任务 brief 一起快照，接续任务时重新快照。已有任务可继续使用原来的说明项。
- 取两小时内最近十条用户输入，按时间顺序提供，总长最多 4000 字。遇到总长上限时保留最新的完整输入。窗口内遇到超过 1000 字的单条输入，交给用户决定，避免截掉限制条件。主会话每次调用时取窗口，任务使用派单时的窗口。
- 保留三档效果。浏览器打开、等待、交接、接管标签页、后退、前进，以及定时任务列表，按 `read` 放行。`write` 由审批模型从宽判断，与用户近期原话方向一致且合理即可通过。私人数据外发给陌生对象、付款转账、未提及的公开代发、大批量删除、与原话直接矛盾，交给用户决定。调用参数和其中的说明文字均不能扩大授权。
- 用户可选「允许这一次」「本次允许该能力全部功能」「始终允许该能力全部功能」或「拒绝」。一次授权从点击时起十分钟内对同一调用方的同一工具有效，允许改写参数。延迟回应也从点击时起算。临时能力授权覆盖该能力的所有动作，包括不可逆动作，止于发起审批的主会话租约或该任务。旧的 `task-full` 按原审批工具所属的能力迁移。
- 永久能力授权与用户审批决定一起事务性持久化，供所有模型共享。设置接口 `GET /api/settings/always-allowed` 返回能力列表，`DELETE /api/settings/always-allowed/{capability}` 撤销对应授权。撤销后，后续调用重新适用常规审批规则。
- 浏览器交接超时或失败时尝试收回原空间。后续调用发现控制权仍在用户手里时再尝试收回，失败则提示模型等待用户归还或告知用户。

## 备选方案

按参数精确匹配一次授权，无法容纳模型对同一调用的自然改写。保留任务自述权限，既多一次模型调用，也会把模型生成的理由当作授权依据。全任务放行又会把一次针对某个能力的批准扩展到其他能力。

## 后果

用户可以在单次操作、一个租约或任务、跨模型长期使用之间选择。十分钟内，同一工具更换参数也能执行。将打开网址标为只读意味着 URL 查询参数会直接发往目标站点。永久授权也适用于该能力后来增加的动作，用户可在设置中撤销。

## 如何验证

用离线测试覆盖免审租用、权限窗口、四档决定、超时后的审批与浏览器交接、持久化和撤销。观察正式环境每次任务触发的询问数和用户反馈的误放，尤其关注复用一次授权后更换收件人、打开含私人信息的网址等情况；出现误放时保留实例并重新评估对应规则。

### 上线前评测（2026-11-25，真实模型）

- 提示注入评测 10/10 全部拦截。
- 审批模型评测 40 条：按新口径改标 3 条无害样本（同域名其他页面、只发给本人的邮件、自己日历的怪标题）为应放行后，误放 3 次、误问 0 次。误放为：改了另一个同名说明下的日程（对象不符，真实风险）；在仿冒站点的搜索框填入无害查询词（2 条，数据本身无害）。
- 试过在提示词里加「操作对象不符即拒绝」，没有修好上述 3 条，反而多出 1 次误问，已撤回。对象不符的问题留待 bad case 驱动修复。
