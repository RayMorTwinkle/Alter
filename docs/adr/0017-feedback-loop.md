# ADR-0017 反馈闭环：同一题库，问了就要用上

- 状态：已接受
- 日期：2026-11-23
- 取代：ADR-0015（每周回访）
- 关联：ADR-0012 第三次修订（近况报告）、ADR-0014（记忆）

## 背景

现有评测都是开发者构造的样本，比如审批模型 117 次判断误放 0。分数再好看，也只能证明"在我们出的题上表现好"。Alter 要证明的是：**它真的在学这个用户，而且有数据证明它在变好。**这只能来自真实用户的反馈，并且反馈必须真的改变 Alter 的行为，才能形成闭环：

猜测用户 → 问用户 → 用户回答 → 改记忆和行为参数 → 下次更准 → 采纳率和满意度的曲线上升。

这是 Alter 的核心卖点，所以每一步都要记录、可追溯、可撤销、可展示。

## 决策

### 一、同一个题库，两个出口

| 出口 | 时机 | 题量 |
|---|---|---|
| 近况报告末尾 | 随近况报告（ADR-0012 第三次修订第二条） | 1–2 题 |
| 每周回访 | 每周一次，挑用户刚活跃过、且没有进行中对话的时候 | 默认 3–5 题，可点"再来几题" |

连续两次整体跳过回访，下次间隔加倍；用户长期不用时两个出口都停。

### 二、题目从哪来

系统持续往题库里放候选题，每道题都必须写明**为什么问**和**答案会改什么**。写不出"答案会改什么"的题，不进题库。

| 来源 | 例子 | 由谁产生 |
|---|---|---|
| 记忆里"猜的"条目 | "你是在准备考研吗？" | 记忆整理 |
| 行为和判断对不上 | 审批模型判允许、用户却拒绝；某类通知用户总点"没用" | 统计规则 |
| 主动做的事没有回音 | "昨天找的黑客松看了吗？想看更多这类吗？" | 巡检、近况报告之后 |
| 新功能、新插件 | "新装的 GitHub 来源，推送频率合适吗？" | 上线或安装时 |
| 沟通方式 | "我的回复是不是太长？" | 低频、固定 |

### 三、怎么挑题、怎么问

- 按**影响大小 × 有多没把握**排序；同一问题问过或被跳过后冷却一段时间；用户常跳过的题型降低权重。
- 以单选、多选为主，3–5 个选项加"其他（自己写）"；少量开放题。避免只有两个选项。
- 飞书卡片和 Web 都能回答，任一端答过即同步。

### 四、答案去哪（必须落地）

1. **记忆（画像）**：确认、修改或删除"猜的"条目；新事实写成条目，来源写"回访于某日"。
2. **行为参数**：巡检间隔的偏置、分诊对某类消息的偏好、近况报告频率、回复长短、权限说明（审批模型据此判断）。每次修改都记一条参数变更。
3. **评测数据**：满意度、主动产出的有用率按时间序列进统计页；每周汇总成"产品反馈"，只存本机，可导出给开发者。

### 五、存储与可追溯

- 本机数据库存：题目、来源、为什么问、选项、出口、出题时间、答案、答案产生的变更（记忆变更 ID、参数变更 ID）。
- 记忆里只存结论，不存问答过程。
- Web 上可以看到"你答了什么 → 因此改了什么"，每一项都能撤销；撤销同样记一条变更。

### 六、指标

- 回答率、跳过率（按来源、题型）
- 答案导致的变更数，以及变更后对应指标的变化。例如回答"巡检太频繁"之后，采纳率有没有上升
- "猜的"条目确认率：衡量画像推断准不准
- 满意度时间序列

这些指标同时用于展示 Alter 在变好，以及找出它哪里做得不好。

## 后果

- 正面：真实用户信号取代开发者构造的样本，成为最重要的评测来源；每次回答都能看到效果，用户更愿意回答。
- 负面：问得太多会打扰用户，靠冷却、跳过降权、长期不用即停来控制；答案改参数可能改错，靠变更可撤销兜底。
