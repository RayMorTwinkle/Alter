# ADR-0026：多用户网关与用户节点

- 状态：已接受
- 日期：2026-11-25
- 相关：#147（网关）、#148（节点程序）、#149（hub 侧节点支持）

## 背景

Alter 要让舍友也能用。舍友的诉求是用 Alter 指挥**他们自己电脑上的**编码代理（Claude Code、Codex、用 DeepSeek 的 opencode 等）。但舍友的电脑不常开，离开宿舍还会断网；只有日程和记忆又没有吸引力。

## 决策

把 Alter 拆成两半：**大脑常开，手按需上线。**

### 一、大脑：网关 + 每人一个实例，跑在管理员的 Mac 上

- 新增 `packages/gateway`：对外唯一入口，负责账号、登录、邀请码注册、管理员界面；登录后按用户把 HTTP、SSE、WebSocket 转发给该用户自己的 Alter 实例。
- **每人一个实例**：独立进程、独立数据目录（`data/users/<userId>/`）、独立端口。记忆、任务、密钥、插件配置天然隔离，现有代码几乎不用改。一个实例约 70 MB 内存。
- 管理员沿用现有正式实例（`data/`，4317，launchd 管理）；其他实例由网关作为子进程拉起、崩溃重启。
- 实例在网关模式下不再自己校验密码，只信任来自本机、带共享密钥头的网关请求。
- 模型配置所有人相同（继承 `.env` 的模型网关设置）。
- 能操作管理员 Mac 的能力（ego 浏览器、命令行/MCP 转接器、自写插件）只在管理员实例启用；其他实例关闭。
- 公网经 SM 的 frp + nginx 暴露网关（HTTPS 子域名）。
- 第一版舍友只用网页；飞书多用户（一个机器人按发送者转发给对应实例）以后再做。

### 二、手：用户电脑上的节点（node）

- 新增 `packages/node`：跨平台（macOS / Windows / Linux）的 Node.js 程序，TypeScript 编写。用户在自己电脑上运行，**主动**用 WebSocket 连到网关，因此不需要公网 IP，校园网 NAT 后也能用。
- 节点上报本机可用的代理（harness），执行大脑派来的任务，把过程事件、审批请求、最终报告回传。
- 第一批代理：Claude Code（官方 Agent SDK）、Codex（`codex app-server` stdio JSON-RPC）、opencode（本机 HTTP 服务）。其他支持 ACP 的代理以后经通用 ACP 适配器接入。
- 代理在用户自己的电脑上、用用户自己的账号和额度运行；管理员 Mac 的文件和浏览器不暴露给其他用户。
- 节点离线时，派给它的任务**排队**，主会话告知用户"电脑上线后开始"；节点上线后自动开始，结束后照常汇报。

### 三、任务结束一定有报告

不依赖外部代理自觉调用工具：

1. 节点经 MCP 向代理提供可选的 `finish({summary, refs})` 工具；调用了就用它。
2. 没调用时，代理一轮结束（Claude 的 `result`、Codex 的 `turn/completed`、opencode 的 `session.execution.*`）后，节点取本轮最后一条助手正文作为报告。
3. 失败、中断、崩溃、超时也必须产生带状态的报告（`failed` / `interrupted`），附最后的输出或错误。

这与 ADR-0025"正文默认发送"同一思路：顺着模型习惯，让框架兜底。

### 四、审批

节点把代理的权限请求（Claude 的 `canUseTool`、Codex 的 approval 请求、opencode 的 permission 事件）转成 `approval.request` 发给大脑，经 broker 与审批模型、四档按钮处理，再把决定传回。外部代理自己的权限规则会先放行一部分操作，因此节点按任务权限档位配置代理的权限模式：`restricted` 用代理最严格的询问模式，`auto` 用其默认模式，`full` 允许代理自行执行。审批覆盖的是"代理问出来的那部分"，这一点在界面与文档中如实说明。

## 后果

- 正面：舍友不需要常开电脑，也能在电脑开着时用手机指挥自己电脑上的代理；安全边界清晰；大脑侧几乎复用现有代码。
- 负面：管理员 Mac 断网时所有人不可用；外部代理的审批只覆盖其主动询问的操作；节点需要在每台电脑上安装。
- 以后：飞书多用户；管理员 Mac 上为用户开隔离代理环境（电脑关机时也能用）；节点打包成单文件可执行程序与开机自启。
