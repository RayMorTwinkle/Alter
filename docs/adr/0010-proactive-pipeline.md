# ADR-0010 主动性：事件 → 预过滤 → 分诊 → 投递 → 反馈 的流水线

- 状态：已接受
- 日期：2026-11-22

## 背景

到 M3 为止，Alter 只在用户开口时工作。插件已经会把新邮件、飞书群消息写进外部事件列表（`Events`），但没有任何东西读它。M4 要让 Alter 自己发现值得告诉用户的事。

主动功能有三个天然的坑：

- **打扰**：推得越多越没人看。核心指标是打扰精准率（推送中用户认为有用的比例），不是推送量。
- **成本**：每来一封邮件就唤醒主会话，token 会随消息量线性增长。
- **注入**：主动处理的输入几乎全是别人写的（邮件、群消息、网页），比用户指令危险得多。

## 决策

**一、流水线分五段，每段可单独计数（这就是漏斗）。**

| 段 | 做什么 | 谁来做 |
|---|---|---|
| 触发 | 外部事件、定时任务、目标复查 | 插件 / 调度器 |
| 预过滤 | 去重、静音名单、规则丢弃（如营销邮件头） | 确定性代码，零 token |
| 分诊 | 判定 立即 / 摘要 / 静默，附一句理由 | 任务模型，**无工具** |
| 投递 | 立即：推到用户在用的入口；摘要：每日定时汇总 | 通知中心 + 各 Surface |
| 反馈 | 打开、有用 / 没用、采纳（用户据此让 Alter 做了事） | 用户在 Web / 飞书点按 |

**二、分诊是"只读进、标签出"。** 分诊调用只看到事件摘要和用户画像、目标的简短摘要，没有任何工具，输出被解析成固定的三选一标签和不超过 80 字的理由。恶意内容最多把一封垃圾邮件标成"立即"（多打扰一次），无法让 Alter 做任何事。

**三、主会话不被每个事件唤醒。** 只有"立即"级通知和每日摘要会进入主会话的上下文（作为不可信数据，带来源）。用户看到通知后说"帮我回一下"，才走正常的派任务和审批流程。

**四、调度器用持久化任务的睡眠实现。** pi-durable 的任务可以睡到指定时间、重启后照样醒来。用户提醒（"明天 9 点提醒我"）、每日摘要、目标复查都是调度项；主会话有创建 / 列出 / 取消调度的工具（效果为 `write-local`）。

**五、目标驱动只派只读任务。** 目标复查时，主会话可以为未过期的目标派 `restricted` 档的调研任务（例如"12 月考试 → 搜往年题"），结果进摘要，不直接打扰；需要对外发送的事只能由用户发起。

**六、两个硬上限。** 安静时段（默认 23:00–08:00，"立即"降级为摘要）和每日主动 token 预算（分诊 + 目标任务合计，超出后当天只做预过滤和记录）。

**七、记忆先落地。** 分诊和目标驱动都依赖 ADR-0005 的画像和目标，因此 M4 第一步是实现画像 / 目标 / 事实三类记忆、主会话的记忆工具和 Web 记忆面板；任务账本已由框架强制写入。

## 备选方案

- **每个事件都交给主会话处理**：上下文和成本随消息量增长，且把不可信内容直接放进有工具的会话，放弃。
- **纯规则分诊**：零成本但判断不了"老板问周报"和"系统周报"的区别；规则只用在预过滤。
- **分诊直接执行动作（如自动回复）**：违反 ADR-0003，分诊输入是数据，不能产生指令。

## 后果

- 新增通知中心（通知、级别、状态、反馈）作为主会话旁边的一类持久化文档，Web 增加通知页，飞书推送"立即"级。
- 每日摘要是一次固定的主会话调用，成本可预测。
- 分诊质量需要单独评测；没有真实反馈数据前，先用人工标注的样本集。

## 如何验证

- 分诊评测：人工标注的事件样本（重要 / 一般 / 噪音），算分诊准确率与"立即"级精准率、召回率；包含植入指令的样本，验证分诊输出始终只是标签。
- 漏斗：触发数 → 预过滤后 → 推送 → 打开 → 有用 → 采纳，按天统计，Web 上可看。
- 成本：每天主动 token 用量不超过预算。
- 推翻条件：真实使用两周后，打扰精准率低于 50%，就收紧"立即"级（例如只对白名单联系人）。
