# ADR-0025 主会话默认发送最终正文，用 stay_silent 静默

- 状态：已接受
- 日期：2026-11-25
- 关联：[ADR-0022 主会话统一通过 send_message 对用户说话](0022-send-message.md)、issue #133

## 原因

实际对话中，模型习惯用正文回答问题、汇报结果，经常在写出完整答案后结束回合，漏掉 ADR-0022 要求的发送调用。飞书用户看不到答案，也很难知道它已经写好。默认发送把主要失败模式从「漏报」变为「多报」。多出的一条提醒容易察觉，用户可以指出哪些情况需要静默，其代价通常小于错过回答或任务结果。

## 决策

删除主会话的 `send_message`。成功结束回合时，core 只取最后一条 assistant 答案，合并其中的正文块。最终答案为空或全为空白时结束投递，中间工具轮的草稿不补发。失败或中止的半截正文只留在网页上。

用户消息按触发本轮的渠道回复。网页回复只在网页显示，飞书私聊回到已配对的飞书，命令行回复回到命令行。巡检、任务报告、近况报告等系统唤醒共用现有的立即通知路径，可推送到飞书。通知和时间线的已发送标记在同一事务提交。飞书只消费通知并沿用投递去重。

主会话可在任一回合调用内部工具 `stay_silent({ reason? })`。静默作用于整轮，包括调用前写的草稿和派出的任务。网页标记草稿并展示可选原因。系统输入末尾提醒模型可选择静默，用户输入保留原文。静默回合派出的任务在报告中提示其来源，主会话仍可决定提醒用户。并入原回合的报告不额外产生一条回复。

## 取代范围

ADR-0022 的单一通知出口、网页回合不推飞书、飞书以纯文本立即投递继续适用。正文默认是草稿、显式发送工具及其 4000 字参数上限、按缺少工具调用记录未回复的规则由本决策取代。`/api/stats` 按唤醒时间统计显式静默回合数。已有会话保留历史记录，升级后不会补发旧草稿。
