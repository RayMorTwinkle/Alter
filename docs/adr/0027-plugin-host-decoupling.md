# ADR-0027 插件通过声明接入核心与 Web 宿主

- 状态：已接受
- 日期：2026-11-26
- 关联：Issue #169、[ADR-0013 插件提供渠道、能力、消息来源](0013-plugins-channels-capabilities-sources.md)

## 背景

ADR-0013 区分了用户通过渠道发来的指令和插件推入的外部数据。原来，主会话、记忆和通知分别维护渠道名单。第三个聊天插件即使能收发消息，它的用户发言也可能漏记，回复也可能发往其他渠道。盯梢参数只接受飞书和邮件，定时任务重载依赖日历插件的名字。Server 直接读取飞书账号和日历对象，负责实现 OAuth、查询日程和监听日历变化。替换插件需要同时修改宿主的多处代码。

改造还要支持已有 SQLite 记录、已排队的任务、使用旧接口的调用方，以及先启动 HTTP 服务、后加载插件的部署顺序。

## 决策

**在输入时确定渠道身份。** 每个 Alter 实例有自己的用户渠道注册表，内置网页和命令行。宿主通过 `startSurface(app, surface)` 管理渠道，在调用 `start` 前注册，在启动失败或停止后注销。`openAlter` 可用 `surfaces` 启动渠道，也可用 `userChannels` 注册由调用方管理的入口。Surface 声明 `id` 和可选的 `label`。`submitMessage` 的第五个参数可覆盖当条消息的显示名称。

`alter.user-input` 持久化 `userChannel`，用户输入还保存 `source` 和 `sourceLabel`。唤醒归因、记忆恢复、最近的用户要求和回复渠道共用同一判定。只有缺少标记的旧记录才按历史渠道名识别；旧飞书调用方仍可按原签名提交消息。消息源继续通过 `events.emit` 提交外部数据，即使其来源名与用户渠道相同也只进入分诊和盯梢。

**按能力发现插件。** 主会话从 `capability.summary` 取得说明，缺省使用能力 ID。盯梢接收任意非空渠道 ID，找到同名插件的 `watchSource` 后调用 `authorize`，补拉时调用 `poll`。例如邮件插件在两个入口都检查 `chatId`。宿主负责时间窗、联系人和会话匹配，以及来源不可用时的提示。

巡检取首个提供 `agenda(days)` 的插件。事件定时任务通过 `scheduleEvents.get/subscribe` 绑定和跟踪事件，旧字段 `calendarEvents` 仍可使用。多个来源同时在线时，创建安排需要能唯一识别事件。安排保存来源 ID，提供者停用期间保留绑定，恢复时重新计算时间；在线来源删除事件会取消相应安排。旧安排首次按事件 ID 查找归属；如果没有来源认领或多个来源返回同一 ID，它会等待可唯一识别的来源。插件替换按序更新注册表及事件订阅。

**Server 按声明装配 HTTP 和 SSE。** 具体插件和配置位于 `installedPlugins` 的装配清单。运行实例可提供 `surface`、`externalDelivery`、`routes` 和 `sse`。外发标记决定通知漏斗何时需要外发回执。路由声明方法、路径与处理器；`setupWeb` 允许插件在缺少凭证或已停用时仍提供配置指南。宿主统一检查网关、会话、受限角色和 JSON 写入要求。飞书声明精确路径的 GET 授权回调，管理员实例可免会话接收回调，插件负责验证一次性 OAuth state。

每个 SSE feed 声明事件名、快照和订阅函数。服务在实例变更时解除旧订阅，为在线客户端推送新快照或清空值。新连接默认获得当前快照；日历客户端继续通过 HTTP 读取初值。实例卸载先撤下路由和订阅，再等待已进入的请求完成并释放资源。旧版 Web 测试注入参数复用插件自身的路由和 feed。

## 备选方案

- 在 core 和 Server 维护统一的已知插件枚举。这样能合并重复代码，但加入新渠道仍需修改宿主；历史记录的含义也会随枚举变化。
- 每个插件自行启动 HTTP 服务和 SSE 连接。这样可隔离实现，但需要重复实现登录、网关校验和重连，浏览器也要管理多条连接。
- 重放时查询当前已启用的 Surface。插件关闭后，之前的发言会失去用户身份，影响记忆和活动统计。

## 后果

增加原生插件只需提供它支持的接口并加入装配清单。插件负责约定路由路径、SSE 事件名、稳定的渠道 ID 和事件 ID，调用方负责通过同一宿主启动和停止 Surface。插件专属 Web 界面仍需客户端实现。当前巡检只读取一个 agenda；如果产品需要合并多个日历，应另行定义去重、排序和来源展示。

## 如何验证

- `packages/server/test/custom-plugin.test.ts` 只在测试装配清单注册虚拟微信插件。它经过真实 HTTP、SSE 和 SQLite，覆盖渠道标签、模型创建盯梢、补拉、消息记忆、回复归属、漏斗、事件提醒及重载后的新旧订阅。
- Core 回归覆盖旧飞书记录、显式标记的自定义渠道、多宿主隔离、旧时间事件接口及事件 ID 冲突。邮件插件测试验证两条盯梢路径都会在连接 IMAP 前拒绝不支持的参数。
- 在 Node 24 下运行 `pnpm -r typecheck && pnpm -r test`，同时检查登录、免会话回调、受限角色和原有日历客户端的兼容性。如果新增渠道仍需修改宿主分支，或者停用插件后历史消息改变归属，应重新审视上述接口。
