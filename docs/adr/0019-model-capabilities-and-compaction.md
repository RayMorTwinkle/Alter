# ADR-0019 模型能力从目录识别；主会话压缩前先存记忆

- 状态：已接受
- 日期：2026-11-23

## 背景

网关模型在代码里写死成同一组能力：上下文窗口 65536、最大输出 4096、支持文字和图片。实际情况：

- 正在用的 `opencode-go/deepseek-v4.1-flash` 与 `opencode-go/glm-5.3` 都是 1M 窗口；
- `glm-5.3` 不支持图片，写死的"支持图片"会把截图发给它；
- 一个浏览器任务在 79 条记录内被压缩了 8 次，主要原因就是窗口被低报。

此前 #96 也踩过同一类坑：模型被声明为只收文字，截图在请求前被剥掉。能力声明应当来自数据，而不是手写常量。

主会话是不结束的对话，迟早会被压缩。pi-durable 默认的总结格式面向编程智能体（目标、约束、进度），主会话真正怕丢的是"欠着的事"：答应过用户的事、还在跑的任务、用户还没回答的问题。

## 决策

**一、模型能力从 pi-ai 内置目录识别。** pi-ai 为每个供应商生成了模型目录（上下文窗口、最大输出、输入模态、思考档位映射）。网关模型 ID 形如 `供应商/模型`，按此在目录中查找；找不到时再按模型名跨供应商匹配。识别到的字段直接用于请求与压缩阈值。

**二、识别不到时可以手动配置。** Web 设置中列出当前使用的每个模型及其能力来源（目录 / 手动 / 默认），可手动填写窗口、最大输出、是否支持图片、思考档位。手动值优先于目录。

**三、压缩阈值。** 默认在上下文达到 400k token 时压缩（用户定），模型窗口更小时按窗口计算。长上下文每一轮都要整段重读，越长越慢、越贵，模型在超长上下文里的注意力也会下降。阈值可在设置中调整。

**四、主会话压缩前先存记忆。** 压缩开始前，给主会话一轮机会把值得长期记住的事实与偏好写进记忆（ADR-0014），然后再总结。

**五、主会话的总结格式自订**，分两段：欠着的事（承诺、进行中的任务、待回答的问题）、最近语境。任务会话沿用默认格式。

## 备选方案

- **自建模型能力表**：要跟着每个供应商更新，pi-ai 已经在维护同样的数据。
- **观察遮罩**（把旧的工具输出替换成占位符）：省 token，但每次改写都会让提示缓存从改写点开始失效，在缓存命中率高的情况下反而更贵。暂不做。
- **用满 1M 窗口才压缩**：压缩次数最少，但每轮成本与延迟随上下文线性增长。

## 后果

- 正面：换模型或接新供应商时不用改代码；纯文字模型不会再收到图片；压缩次数大幅下降。
- 代价：依赖 pi-ai 目录的准确性，目录有误时需要手动覆盖。
- 压缩前多一轮存记忆的模型调用。

## 如何验证

- 当前模型从目录识别出 1M 窗口，`glm-5.3` 识别为纯文字。
- 同类浏览器任务的压缩次数，与 #104 之前的 8 次对比。
- 主会话压缩后能接着回答之前答应过、尚未完成的事。
