# ADR-0023 通过转接器将现成工具注册为插件

- 状态：已接受
- 日期：2026-11-24
- 关联：#122、#87、ADR-0013、ADR-0016、ADR-0021

## 背景

已有的 MCP 服务、命令行程序和公开 OpenAPI 文档的服务，自身已经定义了调用方式。逐个编写 Alter 包会重复维护这些接口，还会增加工具更新后的同步成本。

## 决策

用户在已登录的网页添加转接器。服务端发现工具后生成普通 `AlterPlugin`，通过 `app.replacePlugin` 注册。主会话可租用其能力，任务可调用工具。实际调用经过现有 broker，添加配置即代表用户选择接入，转接器沿用 ADR-0016 修订后的本机运行权限。

| 种类 | 能力 ID | 工具来源 | 默认效果 |
|---|---|---|---|
| MCP | `mcp-<id>` | 官方 SDK 通过 stdio 或 HTTP 发现工具，直接使用输入 schema | 显式只读提示为 `read`，其余为 `write` |
| CLI | `cli-<id>` | 单个 `run` 工具使用固定前置参数、独立 argv 和可选 stdin，帮助来自配置或程序的 `--help` | `write` |
| HTTP | `api-<id>` | OpenAPI 3 的每个 operation 生成工具，支持 path、query、header 参数和 JSON 请求体 | GET、HEAD 为 `read`，其余为 `write` |

每个工具都允许用户覆写为 `read`、`write` 或 `irreversible`。注册时使用生效效果，界面同时显示发现时的默认值。工具名规范化并在同一能力内去重。外部结果带 `details.untrusted`，包括文本、图片和工具错误。

配置和最近成功发现的快照存入数据目录的 `adapters.json`，以 0600 权限原子替换。密钥按转接器 ID 隔离，交给 `openSecrets` 加密存储。配置示例为 `{"headers":{"Authorization":"Bearer {{secret:TOKEN}}"}}`，运行时解析占位符。密钥值通过独立的 `secrets` 字段设置，删除转接器时连同未再引用的密钥一起清理。

原生插件继续承担渠道、事件源等需要宿主生命周期的集成。自写插件继续承载用户或 Alter 编写的专用逻辑。#87 并入本决策，今后 Alter 自己扩展能力时，优先尝试用转接器接入现成工具。

## 备选方案

逐个编写原生或自写插件可以定制交互，但每次接入都需发布代码。为每种协议另建调用与审批通道会重复实现租约、用户授权和审计。

## 后果

配置和效果变更即时生效。发现失败时可以检查原因并刷新，MCP 自动退避重连。停用或删除会撤下工具并关闭连接。CLI 和 stdio MCP 进程拥有服务账号的本机权限；用户把有副作用的工具覆写为只读后，broker 会按只读规则放行。

## 如何验证

使用临时数据目录、SDK stdio 服务、本地 HTTP 服务和 Node 子进程，覆盖发现、参数保真、默认效果、覆写、broker 调用、错误与断线恢复。通过认证接口验证启停、重启恢复、删除注销、密钥清理及配置文件权限。
