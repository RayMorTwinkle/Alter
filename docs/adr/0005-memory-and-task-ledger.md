# ADR-0005 分层记忆，任务账本由框架强制写入

- 状态：已接受
- 日期：2026-11-22

## 背景

主动智能体的价值取决于它有多了解用户：当前目标是什么、帮用户做过什么、东西放在哪。"每个任务完成后记一句话"如果只靠提示词要求，模型一定会漏。

## 决策

记忆分五类：

| 类型 | 内容 | 写入者 |
|---|---|---|
| 画像 Profile | 身份、偏好、说话风格、重要的人 | 主会话主动写 |
| 目标 Goals | "12 月中考试""在找实习"，带期限与状态，**会过期** | 主会话主动写 |
| 事实 Facts | 账号、地址、某人是用户的老板 | 主会话 / 任务 |
| 任务账本 Ledger | "帮用户回复了老板关于周报的消息，聊天记录在 …" | **框架强制** |
| 情节 Episodes | 对话摘要 | 系统定期压缩 |

**任务账本的强制机制**：任务结束的唯一出口是 `finish(summary, refs[])`，`refs` 指向文件、联系人、链接、聊天记录。缺少任一字段则任务无法结束。

其他规则：

- 目标有期限与状态；过期目标转为已完成或待确认，避免主动功能对着过时目标工作。
- Web 端提供记忆面板，用户可查看、修改、删除全部记忆。
- 存储先用 SQLite + FTS5 全文检索；数据量起来、实测检索不够用时再加向量检索。

## 备选方案

- **提示词要求模型记录**：会漏，不可审计。
- **一开始就上向量数据库**：增加运维与跨平台成本，没有数据证明需要。

## 后果

- 任务账本天然成为"Alter 帮用户做了什么"的审计记录，也是使用数据的来源。
- 需要处理记忆冲突（新旧事实矛盾）与隐私（记忆面板必须可删除）。

## 如何验证

- 账本覆盖率：结束的任务中带完整 summary + refs 的比例（目标 100%，由框架保证）。
- 记忆检索命中率：给定问题能否取回正确记忆，建黄金测试集评测。
