# ADR-0018 删除污点，效果只留三档，审批模型直接启用

- 状态：已接受
- 日期：2026-11-23
- 修订：ADR-0004（效果分级）、ADR-0011（审批流程与影子模式）；取代 #3、#44 的污点追踪

## 背景

污点追踪（#3）的初衷：上下文读过外部内容后，对外发送可能是被注入驱使的，因此要审批。实际运行中暴露两个问题：

- **主会话的污点永远为真。** 巡检、分诊、近况报告唤醒主会话时都会打上污点，代码里没有任何清除路径。主会话是不结束的对话，第一次巡检之后就永久带污点，于是租用任何非只读工具都要问用户。一个永远为真的标志不再区分任何东西，只剩打扰。
- **任务几乎都会读外部内容。** 浏览器、邮件、消息来源类任务第一步就是读，污点对任务同样近似恒真。真正起把关作用的一直是"调用是否在权限说明范围内"这一层。

效果分四档（只读、改本地、对外发送、不可逆）也过细：改本地与对外发送的处理方式在去掉污点后没有区别。

审批模型（ADR-0011）默认影子模式，用于和用户真实决定对照。但 Alter 只有一个用户，正式环境一天只攒到个位数对照，影子模式拖慢的是迭代本身。

## 决策

**一、效果只留三档：`read` / `write` / `irreversible`。** `write-local`、`external-send` 并入 `write`。插件清单只能声明这三种；未声明的工具按 `irreversible` 处理。任务自身的控制工具（`finish`、`sleep`、`declare_permissions`）与主会话的 `notify`、记忆和定时安排属于系统内部动作，不经审批（记忆在面板中可见、可撤销，猜测的记忆由回访确认）。能把数据带出去的工具即使看起来是读（如浏览器打开任意网址），也标为 write。

**二、删除污点追踪。** 删除 Taint 文档、已见 URL 列表、租用记录的 tainted 字段，以及统计与时间线中的相关展示。

**三、审批规则。**

| 效果 | 处理 |
|---|---|
| read | 直接放行 |
| write | 审批模型对照权限说明判断：在范围内放行，不在范围内问用户 |
| irreversible | 问用户；选过"本任务全权限"的任务直接放行 |

权限说明的来源：任务用 `declare_permissions` 写的说明；主会话租用工具时，用用户最近的原话（只取用户输入，不取模型输出与工具结果）。审批模型的输入、输出格式与 ADR-0011 第四条相同。

**四、审批模型直接启用。** 设置只剩"开 / 关"，默认开；删除影子模式。关闭时所有 write 都问用户。审批卡片三个按钮：允许这一次 / 本任务全权限 / 拒绝。"按说明允许"成为默认行为，不再需要按钮。1 分钟无人回应时返回"暂未获批"、任务继续做别的，保持不变。

**五、插件接入批准页逐个列出工具及其效果**，让用户在安装时核对效果声明是否诚实（插件不沙箱，见 ADR-0016）。

## 备选方案

- **压缩后清污点**：总结由读过外部内容的模型写成，注入内容可能留在总结里，清了不安全；不清则恒真。两头都不成立。
- **按会话轮次清污点**：外部内容仍在上下文里，清除没有依据。
- **保留影子模式，攒够 50 次对照再切换**：单用户下要数周，期间用户每次都要亲自点。

## 后果

- 正面：主会话租用工具不再每次打扰；规则从"效果 × 污点 × 已见 URL × 任务权限"缩成一张三行的表，用户能预测什么时候会被问。
- 代价：提示注入的防线完全落在审批模型上。权限说明由任务写，任务可能已读过外部内容，说明本身可能被影响；主会话用用户原话做说明，不受此影响。
- 风险由 bad case 驱动修复：用户发现不该放行的调用时告诉 Alter 或开发者，补进离线评测集后调优。

## 如何验证

- 重跑权限决策评测与提示注入评测，记录误放、误问与攻击成功率，和污点时代的结果并列。
- 正式使用中统计：每天问用户的次数、审批模型放行次数、用户事后指出的误放。出现一次真实误放即复盘并补评测样本。
