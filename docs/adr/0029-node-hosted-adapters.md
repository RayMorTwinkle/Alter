# ADR-0029 用户节点托管工具转接器

已接受，2026-11-26。关联 #172、[ADR-0023](0023-adapters.md) 和 [ADR-0026](0026-gateway-and-nodes.md)。

## 决策

转接器由选择它的用户在自己的电脑上运行。每个已配对的 alter-node 可以启动 MCP stdio 子进程、连接 MCP HTTP 服务、包装 CLI 或访问 OpenAPI。管理员实例保留已有宿主转接器。两处共用 `@alter/adapters` 的校验、发现、执行、密钥插值和效果覆写。该包仅使用 Node 内置模块及 MCP SDK，因此节点的单文件安装包无需引入 Brain 的数据库或持久化运行时。

| 部署方式 | 执行身份和可访问的资源 | 可用性与运维代价 |
|---|---|---|
| 管理员宿主运行 | 宿主 OS 账户、文件、网络和本机登录凭据。每用户一个 Brain 进程仍共享 OS 权限。 | 常开，部署简单，仅对管理员开放。 |
| 用户节点运行（方案 B） | 用户自己的 OS 账户、二进制、网络和凭据。用户负责审核添加的程序、服务和工具效果。 | 每台电脑安装节点。离线时收回工具，管理或调用须等节点上线。 |
| 每用户隔离容器 | 可单独限制文件、网络、凭据和进程资源。使用用户电脑上的资源需要额外授权和连接。 | 可以常开，需要镜像维护、资源配额、租户隔离和升级机制。 |

## 权限与数据流

网关按网页会话路由管理请求，按节点 token 的用户前缀路由 WebSocket。目标 Brain 校验 token 并绑定设备身份，只有该实例的配对记录能用于管理。用户实例的宿主策略在路由和组件构造两处生效，覆盖 browser、adapters、ext-plugins、cli、feishu 和 service。节点管理路径独立于宿主策略。

管理请求中的凭据会短暂经过网关和 Brain 的进程内存，再沿配对连接送往节点。公网部署使用 HTTPS/WSS。节点将密钥以 AES-256-GCM 保存在本机，密钥文件和配置文件按用户权限保护。发现快照只公布工具、效果和连接状态。操作系统账户能读取本机密钥，也能启动具备该账户权限的命令。`roots` 约束编码代理的工作目录，CLI/MCP 转接器以用户账户的权限运行。

Brain 以配对记录与转接器 ID 派生能力名。会话租用能力后，由现有 Broker 按效果、授权范围、审批模型及用户决定处理调用。节点收到放行后的请求才执行。配对撤销、连接替换或断开会使进行中的调用失败，离线期间不会排队或重放写操作。断线时某个操作可能已经生效，调用方需先核对结果再重试。
