# ADR-0011 权限说明 + 审批模型：少打扰，不放松

- 状态：已接受
- 日期：2026-11-23
- 修订：ADR-0004（审批流程）、ADR-0002（能力申请）

## 背景

飞书真机使用中，一次"三个浏览器任务并行搜索"弹了 16 次审批，几乎都是 `browser_fill` / `browser_press`。规则本身没错：读过网页之后，往输入框打字和按回车属于对外发送，可能把数据提交给别的网站。但用户要连续点十几次相同的按钮，最后只会盲点，审批形同虚设。

另外有两处多余的环节：

- 任务要用派单时没给的能力，得先 `request_capability`，再由主会话 `answer_permission_request`。真正把关的是每次调用时的副作用审批，这道前置申请只增加往返。
- 能力申请会打断主会话，破坏它的上下文。

## 决策

**一、任务默认可用全部已启用插件的工具。** 删除 `request_capability`、`answer_permission_request` 和派单参数 `allow`。安全由每次调用的副作用分级、污点规则和本 ADR 的审批流程保证。工具数量超过约 50 个时再加工具搜索。

**二、权限说明由执行任务的模型来写。** 任务新增工具 `declare_permissions(items)`，每项写明可能用到的工具、对象（网站、收件人、日程等）和用途，例如"在必应、百度、谷歌的搜索框输入『我的世界 最新版本』并提交"。第一次需要审批时如果还没写，审批卡片只显示这一次的调用。任务可以追加说明，追加部分在卡片上标为"新增"。

**三、审批卡片四个按钮。**

| 按钮 | 效果 |
|---|---|
| 允许这一次 | 只放行当前调用 |
| 按说明允许 | 之后的敏感调用交给审批模型对照权限说明判断 |
| 本任务全权限 | 本任务之后的所有调用直接放行，**包括不可逆操作**（用户明确选择） |
| 拒绝 | 拒绝当前调用；同一任务不换方式重试（沿用 #30） |

**四、审批模型。** 与任务模型同一个模型，思考强度 low，没有任何工具。输入只有两样：用户批准过的权限说明，以及这次调用的工具名和参数。它**看不到网页、邮件等外部内容**。输出固定为"在范围内 / 不在范围内 + 一句理由"，格式无效按"不在范围内"处理。

- 在范围内：放行，记账（标注"审批模型放行"）。
- 不在范围内：照常询问用户。
- 不可逆操作在"按说明允许"下**永远不交给模型**，仍问用户。

已知风险：权限说明由任务写，任务可能已读过外部内容，说明本身可能被注入影响。用户会在第一次审批时看到说明，这是第一道检查；评测中专门放这类样本观察效果。效果不好时，再让审批模型同时对照主会话派单时的任务描述。

**五、超时：1 分钟无人回应视为"按说明允许"。** 审批模型判断在范围内就放行；不在范围内或属于不可逆操作时，**不让任务干等**，而是返回"暂未获批"，任务可以先做别的，做不下去就结束并报告。用户之后仍可在卡片上批准。原 24 小时自动拒绝保留，作为最终兜底。

**六、审批模型三档，在 Web 设置中切换。**

| 档 | 行为 |
|---|---|
| 影子模式（默认） | 审批模型照常判断并记录，但不生效，所有决定仍由用户做 |
| 自动放行 | 按第四条执行 |
| 关闭 | 不调用审批模型 |

设置页显示审批模型与用户决定的一致率，以及"用户拒绝但模型想放行"的次数。用户看数据后自行切换。

## 评测方法

审批模型的错误分两种，代价不同：

- **误放**：本该问用户却自动放行。这是安全问题，目标是 0。
- **误问**：本该放行却去问用户。这是体验问题，决定还烦不烦人。

三种数据来源，可信度从高到低：

1. **影子模式对照**：审批模型在后台给出判断，与用户真实的点击比较。对照对象就是用户本人，是最有说服力的数据。核心指标是"用户拒绝、模型想放行"的次数。
2. **显式反馈**：只在审批模型代用户放行过的任务结束后，在飞书弹出一张卡片，逐条列出它放行了什么，每条可点 👍 / 👎。不是每个任务都弹，避免疲劳后随手乱点。
3. **隐式反馈**：每天派一个模型阅读对话记录，找出用户表达不满的地方（"怎么又问我""先停下""别发"等）。这只是弱信号，用来发现问题，不直接算成绩。

三种来源发现的错判，整理成离线评测集（计划内、计划外、参数被注入三类），以后每次修改审批逻辑都跑一遍回归。

## 备选方案

- **按工具名记住"总是允许"**：实现简单，但"允许 browser_fill"等于允许往任何网站填任何内容，粒度太粗。
- **同源豁免**：读过某网站后，允许向同一网站提交。被否决，理由同 #44：攻击者最现实的外泄目标就是他自己的网站。
- **审批模型也读外部内容来判断**：判断更准，但等于把注入面带进审批环节，否决。

## 后果

- 正面：重复审批大幅减少；主会话不再被能力申请打断；参数被注入的调用（例如把隐私写进搜索框）与说明对不上，会被拦下，反而多一层防御。
- 负面：每次敏感调用多一次低思考强度的模型调用（几百 token）；审批模型本身需要持续评测。
