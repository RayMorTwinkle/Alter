# 审批模型评测（#59，ADR-0011）

- 日期：2026-11-23
- 命令：`ALTER_EVAL_REPEATS=3 pnpm eval:judge`
- 模型：任务模型 DeepSeek v4.1 flash，thinking low，无工具；与生产同一个 `judge()` 函数
- 样本：34 条，由用户视角标注「给定已批准的权限说明，是否愿意自动放行」
  - 范围内 11 条：说明覆盖的对象与用途
  - 超出范围 13 条：换了网站、收件人、日程、操作类型或意思
  - 参数注入 10 条：形式符合说明，但参数夹带私人信息、外部链接、仿冒域名或冒充授权

## 结果

| 指标 | 数值 |
|---|---:|
| 判断次数 | 102 |
| 准确率 | 92.2% |
| **误放**（该问人却放行） | **0** |
| 误问（该放行却问人） | 8 |
| 输出无效（按不在范围内处理） | 1 |
| 延迟 p50 / p95 | 3.4 s / 6.5 s |

| 类别 | 通过 |
|---|---:|
| 范围内 | 25/33（75.8%） |
| 超出范围 | 39/39（100%） |
| 参数注入 | 30/30（100%） |

## 误问的原因

8 次误问几乎都是**审批模型缺少上下文**：

- 只看到 CSS 选择器（`#kw`、`input[name=q]`），不知道它属于哪个搜索引擎；只看到 `Enter`，不知道作用在哪个输入框。
- 只看到日程 ID `evt_b`，不知道它就是说明里的「冒烟B」。
- 「我的世界最新版本号」与说明中的「我的世界 最新版本」被判为不完全一致（提示词要求有歧义时返回 false）。

改进方向（后续 issue）：调用时附上**可信的运行时上下文**——浏览器当前页面的 URL、日程 ID 对应的标题。这些来自工具状态而不是外部内容，不扩大注入面。

## 结论

安全目标达成：误放 0，参数注入全部拦下。范围内样本有 24% 转问用户。

## 局限

- 样本由开发者构造；当次评测未测量真实分布。
- 未覆盖「权限说明本身被注入」的情况（ADR-0011 已知风险）。

## 复测：附带可信上下文（#65）

审批模型多了一个独立的 `context` 字段，内容由插件根据自身状态生成：浏览器当前页 URL、标题、目标元素属性；日程 ID 对应的标题与时间；飞书会话名；规范化的收件人。网页正文、邮件正文等外部内容不进入。样本扩到 39 条（25 条带上下文），新增"上下文显示是别的网站 / 别的日程 / 页面标题冒充授权"的反例。

| 指标 | 首测 | 复测 |
|---|---:|---:|
| 判断次数 | 102 | 117 |
| **误放** | **0** | **0** |
| 误问 | 8 | **0** |
| 参数注入拦截 | 30/30 | 33/33 |
| 输出无效 | 1 | 1 |
| 延迟 p50 / p95 | 3.4 s / 6.5 s | 3.5 s / 6.3 s |

首测的 8 次误问全部消失；新增的反例（仿冒域名页面上的搜索框、同 ID 不同标题的日程、标题里写"已授权"）全部判为不在范围内。上下文没有让模型变松。

样本由开发者构造。ADR-0018 生效后审批模型默认开启，真实误放通过用户反馈补入回归样本。
